# SPEC 集成方案变更：改用 SPEC CPU2017 官方源码 · 用户自备 · 设备端编译

> 变更日期：2026-10-13
> 状态：**方案变更已确认，待落地**（本文只描述新方案与边界，不代表任何 App 源码修改/构建/设备实测已完成）
> 影响工作包：K（SPEC 集成）全部；连带 K5 编译页面、K6 三档输入、K7 工具链实体、K8 可追溯性
> 变更驱动因素：**合规性要求**

---

## 0. 变更摘要

| 维度 | 原方案 | 新方案 |
|---|---|---|
| 套件 | 自实现 "SPEC CPU 2026 移植版"（spec_gcc / spec_femflow / spec_graph500 / spec_sealcrypto） | **SPEC CPU2017 官方基准源码** |
| 基准 | 3 个自实现工作负载 | **519.lbm_r、508.namd_r、502.gcc_r、557.xz_r、510.parest_r、505.mcf_r** |
| 源码来源 | 随项目源码/APK 预编译分发 | **用户自行提供**（自购 ISO / 已安装树），项目不打包、不分发 |
| 编译时机 | 开发期预编译，随 APK 分发多档 .so | **设备端编译**（用户自定义编译参数） |
| 前置条件 | 装 APK 即可跑 | **必须先由用户导入源码并编译成功，才能进行测试** |
| 结果口径 | 内部相对基线（已合规） | 不变：内部相对自标定基线，**非 SPEC 官方成绩** |

一句话：**SPEC 项目从"内置负载"改为"用户自带源码 + 设备端按需编译"的合规形态。**

---

## 1. 合规硬约束（不可协商）

1. 仓库、APK、构建产物、证据包中**不得包含**任何 SPEC 源码、输入数据、参考输出、SPEC 工具二进制（specperl/specmake/specxz/spectar 等）。
   - 落地校验：CI/本地脚本扫描 apk 与仓库，命中 SPEC 源码特征即失败。
2. 源码只由用户提供；导入时校验**套件版本与文件哈希**，并把来源哈希写进结果元数据。
3. 结果一律标注"内部相对基线 / 非 SPEC 官方成绩"，不显示 SPECratio 等官方指标，SPEC 结果禁用分享（沿用 K5 既有规则）。
4. 首次导入时展示许可提示与用户须知，用户确认后方可继续。
5. 自研 spec_*.cpp 不再以 "SPEC" 名义对外呈现（改名或退役，见 §6）。

## 2. 选用的 6 个基准（含本机对官方 v1.1.9 套件的实测清点）

| 基准 | 语言 | 源文件数 | 体积 | 外部依赖 | 设备端编译难度 | 覆盖维度 |
|---|---|---|---|---|---|---|
| 519.lbm_r | C | 7 | 76 KB | 无（-lm） | ★ 易 | 内存带宽、浮点 |
| 505.mcf_r | C | 29 | 188 KB | 无（-lm） | ★ 易 | 整数、分支/指针追逐 |
| 557.xz_r | C | 181 | 1.6 MB | 自带 xz 源码 | ★★ 中 | 压缩、整数 |
| 508.namd_r | C++ | 39 | 348 KB | Charm++ 运行时 | ★★★ 较难 | 分子动力学、浮点 |
| 510.parest_r | C++ | 2 414 | 28 MB | deal.II（自带） | ★★★★ 难 | 有限元、巨型模板 |
| 502.gcc_r | C | 706 | 38 MB | 自带 GCC 源码 | ★★★★ 难 | 编译器、整数 |

**共同点：全部为 C / C++，不涉及 Fortran** —— 设备端无需 Fortran 前端（官方套件中 503/521/527/549/554/628 等 Fortran 基准因此不入选）。合计约 3 376 个文件、68 MB，不含输入数据。

输入数据（test / train / refrate 三档）同样属于 SPEC 套件，**必须由用户提供**；未导入输入数据时只能编译不能跑分。

## 3. 目标数据流与状态机

```
用户许可套件(ISO/已安装树)
   │  导入(SAF 目录选择 / zip / adb push)
   ▼
校验(套件版本 + 文件哈希 + 完整性)
   ▼
源码暂存(app 私有目录, 不入库不分发)
   ▼
设备端编译(clang + lld, 用户自定义参数, 独立子进程)
   ▼
产物校验(产物哈希 + 正确性 oracle)
   ▼
运行(温控隔离, 输入数据由用户提供)
   ▼
结果(源码哈希 + 工具链 + 完整参数 + 产物哈希 + 环境)
```

状态机（SPEC2017 项目专用，未到"已完成"不得显示任何成绩）：

`待导入 → 已导入 → 已校验 → 编译中 → 编译完成 / 编译失败 → 正确性校验中 → 测试中 → 结果计算中 → 已完成`

任一步失败即进入明确的失败终态（编译失败 / 正确性失败 / 温控受限 / 输入缺失），不得以部分结果冒充完整成绩。

## 4. 设备端编译设计

1. **编译器来源**（按优先级，可并存）
   - ① 随应用打包精简 LLVM/clang + lld + libc++（LLVM 为 Apache-2.0 with LLVM Exceptions，可再分发；不含任何 SPEC 内容）；
   - ② 复用设备已有 clang（Termux、自定义 ROM、厂测镜像）；
   - ③ 用户指定工具链路径（高级选项）。
2. **执行隔离**：编译在独立子进程执行（避免主进程 OOM/卡顿），限制并发度，编译前做磁盘/内存/温控预检，支持超时与取消，日志落盘可导出。
3. **参数模型**
   - 结构化：优化级别（-O0/-O2/-O3/-Ofast）、目标微架构（-mcpu/-mtune/-march）、语言标准、LTO、PGO、浮点语义开关；
   - 原始附加参数：允许用户追加 raw flags，但需白名单/黑名单校验（禁止 -o 覆盖产物路径、禁止写入导入目录等）；
   - **所有参数原样记入结果元数据**（K8）。
4. **构建配方（recipe）**：每个基准一份版本化配方，描述文件清单、必需宏（-DSPEC、-DSPEC_LP64、-fcommon、-fgnu89-inline 等）、语言标准、链接库、产物名、已知的编译器版本适配。配方与 SPEC 套件版本绑定（1.0.5 与 1.1.9 分支不同）。
5. **与 612 组 SPEC-Matrix 的关系**：五维矩阵（负载 × 档位 × 优化激进度 × 硬件/工具链实体）继续有效，但"负载"= 上述 6 个官方基准，"构建任务"发生在设备端；配置数 / 构建任务数 / 成功产物数 / 有效结果数分别统计，口径不变。

## 5. 正确性校验（逐基准，导入时从 Spec/object.pm 解析判定规则）

| 基准 | 判定方式 | 依据字段 |
|---|---|---|
| 519.lbm_r | 输出数值容差比较 | floatcompare / calctol |
| 505.mcf_r | 输出与参考输出比较 | 输出比对 |
| 557.xz_r | 解压结果 sha256 == 原始输入 sha256 | 自带校验 |
| 508.namd_r | 能量/输出数值容差 | floatcompare / calctol |
| 510.parest_r | 输出数值容差 | floatcompare / calctol |
| 502.gcc_r | 生成代码功能校验 + 可重复性 | 输出比对 |

**仅编译成功不等于测试有效**；正确性失败的结果不计入有效成绩。

## 8. 本轮验收口径

1. 仓库/APK/产物中不含 SPEC 源码、输入数据与 SPEC 工具二进制（脚本可校验）。
2. 未导入源码 → SPEC2017 项目必须为"未就绪"，不得产生任何成绩。
3. 编译失败、正确性失败、输入缺失、温控受限分别呈现，不计入有效成绩。
4. 任一结果可追溯到：源码哈希 + 完整编译参数 + 工具链版本/哈希 + 产物哈希 + 设备环境。
5. 结果文案明确"内部相对基线，非 SPEC 官方成绩"。

## 9. 风险与待裁定

| 风险/待裁定 | 说明 |
|---|---|
| 设备端编译耗时与发热 | 502.gcc_r / 510.parest_r 在手机上可能 10 分钟以上，必须可取消 + 温控隔离 |
| 设备存储占用 | 输入数据 GB 级（refrate 档更大），需用户可见的空间预检 |
| 新旧 clang 差异 | 官方源码较老，可能出现隐式函数声明等错误，需配方级适配（-Wno-error / -std=gnu89） |
| 用户源码版本不一致 | 1.0.5 / 1.1.x 需分支配方与哈希校验（本机已实测两版差异：29 个源文件、9 个基准） |
| 打包 clang 的体积与 ABI | 需评估 APK 体积增量与目标 ABI 覆盖范围 |
| 自研 spec_*.cpp 处置 | 需产品裁定：改名保留为微基准，还是退役 |
